# 01 收集方案：去哪里找动作，怎么判断能不能用

> 目标：用最少时间找到「有动画、许可干净、能直接用」的素材，避免下回来一堆不能用的东西。

## 一、先明确要什么

动手前先写下三行，不然一定跑偏：

1. **用途**：验证/内部看 → 许可宽松些；要进商业包 → 只收 CC0 / CC-BY
2. **类型**：人形 / 四足 / 多足虫类 / 怪兽 / 飞行 / 水生
3. **格式要求**：引擎吃什么（Godot 偏 glb，Unity 偏 fbx，老管线吃 bvh）

## 二、源的优先级

按「能批量 + 许可清晰」排序，从上往下用：

| 优先级 | 类型 | 说明 |
|---|---|---|
| 1 | 官方样例库（Khronos、three.js、Babylon） | 许可清楚、直链稳定、量小但质量高 |
| 2 | GitHub 开源包 | 能列文件、能直下、许可写在 LICENSE |
| 3 | itch.io 免费包 | 免登录，但要过 CSRF；独立作者多，风格杂 |
| 4 | OpenGameArt | 许可标注规范，条目少而杂 |
| 5 | 学术数据集（CMU、SFU、LAFAN1） | 量大、格式老、许可多为研究用 |
| 6 | 商城免费区（TurboSquid 等） | 要登录，基本放弃 |

## 三、四个检索套路

### 1. DuckDuckGo HTML 端点（不需要 key）

```bash
curl -s -A "Mozilla/5.0 (X11; Linux x86_64)" \
  "https://html.duckduckgo.com/html/?q=<url编码关键词>" -o /tmp/s.html
grep -oE 'uddg=[^&"]+' /tmp/s.html | head -20
```

结果里的链接是 `uddg=` 后面 url 编码过的，解码后才是真实地址。

### 2. GitHub 仓库 + 文件树

```bash
curl -s "https://api.github.com/search/repositories?q=<词>&sort=stars&per_page=20"
curl -s "https://api.github.com/repos/<owner>/<repo>/git/trees/HEAD?recursive=1"
```

拿到文件树后按扩展名筛 `.glb/.gltf/.fbx/.bvh`，再按生物名筛一遍，比人工翻目录快十倍。tree 为空就试 `main` / `master`。

### 3. itch.io 免费包

流程：**取页面 → 抠 csrf_token 和 upload_id → POST 换真实地址 → 下载**。见 `skill/action-library/SKILL.md` 里的命令块。

### 4. 关键词表

- 虫类：`beetle` `ant` `spider` `scorpion` `centipede` `cockroach` `crab` `worm` `insect swarm`
- 怪兽：`dragon` `wyvern` `golem` `troll` `slime` `undead` `kaiju` `beast` `monster`
- 四足：`wolf` `boar` `deer` `horse` `fox` `bear` `raptor` `dinosaur`
- 水生/飞行：`shark` `octopus` `fish` `bat` `phoenix` `bird`
- 提高命中率：`low poly` `PSX` `stylized` `game ready` `rigged` `cc0` `animation pack`

## 四、判断「值不值得下」

下之前问五个问题：

1. **有动画吗**：只有网格的直接跳过。看描述里有没有 `animated` / `animations` / `walk cycle`
2. **是骨骼动画还是形变**：morph target 也能用，但不能重定向到别的骨架上，得单独归类
3. **许可是什么**：CC0 / CC-BY / 研究用 / 不明。不明的一律按非商用
4. **要账号吗**：要登录、要邮箱、要付费 → 跳过并记录
5. **体积合理吗**：单文件超 500 MB 先报备

## 五、下载纪律

- 先 `HEAD` 探一遍状态码再批量下，别让脚本对 404 空转
- 并发别开太大（4–8 个），遇到 403/429 退避
- 长任务用 `setsid nohup ... < /dev/null &`，日志单独落文件
- 下载完立刻校验：`unzip -t`、文件头字节、文件数
- 一次只加一类源，先把这一类跑通再扩，别一上来铺十个源

## 六、记录什么

每下一个源，在清单里留一行：

```json
{
  "source": "来源英文名",
  "source_url": "原始页面",
  "license": "CC0 / CC-BY 4.0 / research-only / unknown",
  "author": "作者（CC-BY 必须）",
  "raw_file": "01_原始下载/xxx/pack.zip",
  "format": "fbx | glb | bvh",
  "clips": ["walk", "run", "attack"],
  "morphology": "四足",
  "reason": "分类理由，20 字内",
  "usable_commercial": true
}
```

清单是以后唯一能追责的东西，别省。

## 七、这次实际遇到的结论

- **Google Drive 文件夹**能抓到文件 ID，但 `uc?export=download` 常返回空响应头 → 不值得死磕，找镜像更快
- **Sketchfab / TurboSquid / CGTrader** 的免费资源几乎都要登录 → 直接跳过
- **Poly Pizza** 的 API 要 key → 没 key 就别绕
- **Godot 资产库**用 `filter=` 查生物类经常返回空，要配合 `category` 参数或直接看网页
- **three.js 的动物模型是形变动画**，不是骨骼动画，入库时必须标清楚
