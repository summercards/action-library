# 02 建库方案：从一堆压缩包到一个能用的动作库

> 目标：动作素材能长期找得到、看得懂、用得对。重点不是「存下来」，是「三年后还能用」。

## 一、目录：六层，各管一件事

```text
~/动作库/
├── 00_说明与索引/     规则、资源总表、授权记录、库文件（library.db）
├── 01_原始下载/       原封不动的压缩包，按来源分目录
├── 02_动作数据/       解开、转过格式的原始动作
├── 03_整理后/         统一骨架、按用途分类的成品
├── 04_临时/           解压、试验、待删
├── 05_导出给引擎/     给 Godot / Unity 直接吃的成品
└── 90_网页系统/       预览站与工具
```

**层次的意义在于「可回滚」**：任何一步判断错了，退回上一层重来，原始包永远还在。

一条动作只能往上走：`01 → 02 → 03 → 05`，不能跳级，不能回退改原件。

## 二、入库六步

| 步 | 动作 | 产出 | 核对什么 |
|---|---|---|---|
| 1 | 落盘 | `01_原始下载/{来源}/` | 文件名保持原样、体积对不对 |
| 2 | 解压 | `04_临时/` | 文件数、动作时长、骨骼有没有名字 |
| 3 | 校验 | —— | `unzip -t`、文件头字节 |
| 4 | 转格式 | `02_动作数据/{格式}/` | 转完能不能播 |
| 5 | 整理 | `03_整理后/{分类}/` | 统一骨架、剪首尾空帧 |
| 6 | 登记 | 总表 + 授权记录 | 一行一个资源，状态改原行 |

## 三、命名与状态

**命名**：`来源_动作_时长_授权.扩展名`
例：`Mixamo_run_1.2s_CC0.fbx`、`LAFAN1_walk1_subject1_8.4s_UbiSoft.bvh`

只用英文数字下划线。同一来源的批量文件保留原始编号，不改序。

**状态只有六个**：`已下载` / `已解压` / `已转换` / `已整理` / `已入库` / `废弃`

## 四、许可红线

| 授权 | 能进商业包 | 要署名 | 能进的层 |
|---|---|---|---|
| CC0 / 公有领域 | 能 | 不用 | 02 / 03 / 05 |
| CC-BY | 能 | **必须**（作者 + 原链接） | 02 / 03 / 05 |
| 仅限非商用 / 研究 | 不能 | —— | 只能 01 / 02 |
| 授权不明 | 不能 | —— | 只能 01 / 02，先查清 |

标「非商用」的可以留在 `01_原始下载/`，**不许进 03 和 05**。这一条比什么都重要：库里混进一条来路不明的素材，以后整个商业包都要重审。

## 五、数据库与标签

`00_说明与索引/library.db`（SQLite）是索引，不是权威——权威永远是磁盘上的文件。

主表 `assets` 关键字段：`id` / `name` / `path` / `format` / `source` / `duration` / `size` / `thumb` / `fav`。

**标签按维度分，不要塞进一个字段**：

| 维度 | 取值示例 |
|---|---|
| 动作类型 | 走 / 跑 / 跳 / 待机 / 攻击 / 受击 / 死亡 / 舞蹈 / 搬运 / 攀爬 |
| 速度 | 静止 / 慢 / 中 / 快 |
| 强度 | 轻 / 中 / 重 |
| 对称性 | 对称 / 左偏 / 右偏 |
| 用途 | 循环 / 单次 / 过渡 |
| 来源 | CMU / LAFAN1 / Mixamo / Quaternius / SFU … |
| **形态**（生物库） | 四足 / 六足 / 八足 / 多足 / 蛇形无足 / 鸟类双足 / 水生 / 龙类 / 翼类 / 软体 / 未知 |

生物库还要单独标 `人形=是/否`。

**打标方法**：长动作先按速度突变切段，再逐段定性。整段贴一个标签必错——一段 30 秒的动捕里可能同时有走、跑、停。

打标要写依据，20 字内，写不出来说明你没看懂这条动作。

## 六、缩略图

批量给每条动作渲一张 360×360 的图，人一眼能认出是什么动作。

- Blender 无头：`blender -b -t 4 --factory-startup -P tools/thumb_render.py -- <动作> <输出.png>`
- 取景按包围盒算，`margin=2.1`、`dist = size * margin * 0.82`，不然角色顶出画面
- Cycles + GPU（OPTIX/CUDA）+ 降噪，采样 12–16
- 超时 45 秒，失败只标记，不阻断入库
- **先渲一张自己看**：粉紫 = 贴图丢了，纯白 = 材质没赋上，黑图 = 灯光或相机错了

## 七、预览站

单文件 Python 服务，一个端口同时给页面、API、文件，不依赖框架。

```bash
cd 90_网页系统 && python3 server.py     # 8099
./start.sh                              # 后台跑，pid → server.pid，日志 → logs/server.log
```

前端 three.js（放 `vendor/`，用 importmap 引用），BVH 用 `BVHLoader`，glb 用 `GLTFLoader`。

关键接口：

- `GET /api/assets?page=&q=&tag=` 分页列表
- `GET /api/tags` 标签与计数
- `POST /api/fav` 收藏
- `POST /api/import` 导入新文件
- `GET /files/{id}` 原文件（Range 支持，视频能拖进度）
- `GET /api/rig/models|animations|jobs`、`POST /api/rig/apply`、`GET /api/rig/file` 套动作用

## 八、套动作（重定向）

把库里的动作搬到用户自己的角色上，产出带动画的 GLB + 预览视频 + 封面。

**算法**：逐帧「源姿态 × 源静止姿逆 × 目标静止姿」换算后写关键帧。

**不要用**世界空间 `COPY_ROTATION` 约束 + `nla.bake`——骨架会扭，出图也不对。

**必须处理的情况**：

| 情况 | 处理 |
|---|---|
| 骨骼少于 12 根对不上 | 直接失败，别硬套 |
| 找不到胯骨 | 失败，无法定位角色 |
| 只有动画没网格的 FBX | 渲不出源模型，改数值核对（静止姿差、逐帧最大偏差、平均偏差） |
| 贴图丢失 | 支持 zip 上传，模型 + 贴图目录一起解 |
| 跑步/跳跃出画 | 预览镜头跟随胯骨 |

**预览参数**：360×360、24 帧、Cycles GPU、采样 12/16 + 降噪。24 帧只够看循环的片段，长动作要另开「整段预览」。

## 九、验收（每阶段都要做，不许跳）

1. 文件头校验（glb=`glTF`、bvh=`HIERARCHY`、fbx=`Kaydara FBX Binary`）
2. Blender 抽样 ≥5 条，确认有骨架、有动画帧数
3. 缩略图抽样看图
4. `curl -s -o /dev/null -w "%{http_code}" .../api/assets` 是 200
5. 无头 Chromium 跑一遍页面，控制台异常必须为 0
6. 截图必须开 `--enable-unsafe-swiftshader --use-gl=angle --use-angle=swiftshader`，否则空白

**不接受「脚本说成功」**。脚本说成功只代表它没崩，不代表产物对。

## 十、空间与安全

- 只允许删 `04_临时/` 和标 `废弃` 的条目，其余要人点头
- 原始下载包永不修改、永不删除
- 不在这台机器上放私人资料
- 不自动上传到任何站点
- 磁盘余量低于 15% 就停下来清理，别下到满

## 十一、这套方案实际跑出来的规模

截至 2026-11-03：2707 条（CMU 2535 / LAFAN1 77 / Quaternius 45 / SFU 44 / Khronos 6 + 逐步补人形与非人形），格式 bvh 2656 / glb 51，缩略图全覆盖。

维护节奏：新增一个源 → 走完六步 → 打标 → 渲缩略图 → 跑验收 → 记总表。不要攒着一起做，攒完就没人愿意做了。
